# 향후 계획 (Next Steps)

## 1. 즉각적 후속 조치
- **Baseline 동결 및 공유**: 본 보고서에서 확정된 `production technical_score` 수치들을 프로젝트 문서(docs/) 및 캡스톤 결과물에 공식 기록합니다.
- **테스트 명단 보존**: 평가에 사용된 4,967장의 이미지 ID 및 매니페스트 파일을 별도 관리하여, 향후 모든 실험에서 동일한 데이터로 비교가 가능하도록 합니다.

## 2. 향후 모델 개선 규칙 (Success Rule)
새로운 기술품질 모델 제안 시, 다음 조건을 충족해야 프로덕션 교체 대상으로 고려합니다.
- **동일 데이터셋 평가**: 확정된 4,967장의 Image-level Test Split에서 평가를 수행해야 합니다.
- **지표 우위 입증**: 3대 데이터셋(KonIQ-10k, SPAQ, FLIVE) 전체에서 현재 Baseline보다 높은 SRCC와 낮은 MAE를 동시에 달성해야 합니다.
- **스케일 유지**: 출력 점수는 반드시 0..100 범위를 유지해야 하며, 특정 도메인에 치우친 편향(Bias)이 현재보다 낮아야 합니다.

## 3. 중단 조건 (Stop Conditions)
다음 상황 발생 시 해당 모델의 실험을 즉각 중단하고 설계를 재검토합니다.
- 특정 테스트 데이터셋에서 SRCC가 0.80 미만으로 하락하는 경우 (KonIQ, SPAQ 기준).
- 특정 테스트 데이터셋에서 MAE가 15.0을 초과하는 경우.
- 출력 점수가 0..100 범위를 벗어나는 수치적 오류가 발생하는 경우.
- 안드로이드 실제 단말에서의 추론 결과가 오프라인 평가 결과와 1% 이상의 오차를 보이는 경우.

## 4. 금지 사항 (Forbidden Actions)
- **임의의 공식 변경 금지**: 충분한 벤치마크 데이터 없이 현재의 4/7, 3/7 가중치 공식을 수정하지 않습니다.
- **C6 프로덕션 적용 금지**: 현재 성능 우위가 증명되지 않은 C6 모델을 프로덕션 scoring 로직에 포함시키지 않습니다.
- **평가 데이터 혼용 금지**: 이미지 전체(Image-level) 지표와 패치 단위(Patch-level) 지표를 섞어서 보고하지 않습니다.
- **무분별한 학습 금지**: 본 baseline 보고서가 공식 문서화되기 전까지는 새로운 모델 학습을 시작하지 않습니다.
