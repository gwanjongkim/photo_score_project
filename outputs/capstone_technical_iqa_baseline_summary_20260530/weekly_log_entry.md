# 주간 연구 로그 (2026년 5월 5주차)

## 1. 이번 주 목표
- 기술품질(Technical IQA) 평가 모델의 성능 기준선(Baseline) 확립
- 신규 후보 모델(C6)의 프로덕션 적용 가능성 최종 검증
- 관련 연구(Paper) 프로토콜을 따르는 공식 벤치마크 환경 구축

## 2. 수행 작업
- **데이터셋 감사(Audit)**: KonIQ-10k, SPAQ, FLIVE 데이터셋의 공식 논문 프로토콜 확인 및 로컬 데이터 검증
- **매니페스트(Manifest) 구축**: 논문에서 정의한 테스트셋 분할 방식(Train/Val/Test)에 따른 4,967장의 공식 평가 데이터 명단 생성
- **정량 평가 수행**: 기존 Standalone 모델 2종 및 Production 앙상블 모델에 대한 0..100 스케일 성능 측정
- **코드 감사(Source Audit)**: `src/infer/select_best_shots.py` 등 실제 엔진 소스 코드를 분석하여 프로덕션 점수 산출 공식(4/7 KonIQ + 3/7 FLIVE) 확인
- **결과 분석**: SRCC, PLCC, MAE 지표를 활용한 모델 간 비교 분석 및 시각화 리포트 작성

## 3. 사용 데이터셋
- KonIQ-10k (MUSIQ 프로토콜, 2,015장 테스트)
- SPAQ (공식 테스트셋, 1,125장)
- FLIVE/PaQ-2-PiQ (IQA-Toolbox 표준, 1,827장 이미지 테스트)

## 4. 주요 실험 결과
- **Production 모델의 견고함**: SPAQ 데이터셋에서 단독 모델들보다 높은 **SRCC 0.8730** 기록.
- **오차 안정성**: KonIQ 데이터셋에서 단독 모델 대비 MAE가 **5.18에서 3.26**으로 개선됨.
- **보류된 작업**: C6 모델은 안드로이드 단말과의 수치 일치성은 높으나, 현재 프로덕션 앙상블 모델의 성능을 압도하지 못해 프로덕션 교체 대상에서 제외함.

## 5. 실패 및 보류 내용
- **C6 Production Replacement**: C6 모델이 기존 앙상블 모델 대비 뚜렷한 성능 우위를 보이지 않아 프로덕션 적용을 보류하고 로그/디버그 용도로만 유지하기로 함.
- **Patch-level Evaluation**: 이번 단계의 시간 제약으로 인해 이미지 전체 평가에 집중하였으며, 패치 단위 정밀 평가는 향후 과제로 이월함.

## 6. 최종 판단
- 현재 서비스 중인 `production technical_score`가 학계 표준 데이터셋에서도 가장 안정적인 성능을 보이므로, 이를 프로젝트의 **공식 성능 기준선(Baseline)**으로 확정함.

## 7. 다음 주 계획
- 확정된 Baseline을 바탕으로 모델 경량화(Distillation) 가능성 타진
- 기술품질 외 미적품질(Aesthetic Score) 부문에 대한 동일한 방식의 baseline audit 시작
- 안드로이드 앱 내에서의 런타임 성능 프로파일링 및 최적화 방안 검토
