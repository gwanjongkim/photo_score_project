# A-cut 기술품질 평가 모델 기준선 확정

## 1. 목적
본 연구의 목적은 사진 선별 엔진의 핵심 지표인 '기술품질(Technical IQA)' 평가 모델의 신뢰성을 검증하고, 향후 성능 개선의 척도가 될 공식 기준선(Baseline)을 확정하는 데 있습니다. 최근 개발된 C6 모델을 포함하여 여러 후보 모델의 실효성을 검토하였으나, 최종적으로는 현재 서비스 중인 `production technical_score`가 가장 안정적이고 우수한 일반화 성능을 보임을 확인하였습니다. 이에 따라 기존 프로덕션 모델을 공식 기준선으로 확정하고, C6는 로그 분석 및 디버깅 용도로만 유지하기로 결정하였습니다.

## 2. 관련 연구 기반 평가 프로토콜
평가의 객관성을 확보하기 위해 임의의 벤치마크 대신, IQA 학계에서 널리 사용되는 공식 데이터셋과 평가 프로토콜을 그대로 준수하였습니다.
- **KonIQ-10k**: MUSIQ 논문 방식의 80/20 무작위 분할 (Run_01 Test: 2,015장)
- **SPAQ**: 스마트폰 촬영 사진 특화 데이터셋 (Official Test: 1,125장)
- **FLIVE/PaQ-2-PiQ**: 대규모 실제 왜곡 이미지 데이터셋 (IQA-Toolbox 표준 Image-Test: 1,827장)
- **총 평가 규모**: 4,967장의 이미지 레벨 테스트 데이터

*참고: 본 단계에서는 전체 이미지의 품질을 평가하는 image-level 테스트에 집중하였으며, 패치 단위(patch-level) 평가는 제외되었습니다.*

## 3. 평가 대상
- **KonIQ Standalone**: KonIQ-10k 데이터셋으로 학습된 TFLite 모델
- **FLIVE Standalone**: FLIVE 데이터셋으로 학습된 TFLite 모델
- **Production Technical Score**: 위 두 모델을 결합한 현재 서비스 중인 앙상블 모델
- **C6 (참고)**: 안드로이드 런타임 검증을 마친 후보 모델 (프로덕션 적용은 보류됨)

## 4. Production Technical Score 공식
현재 A-cut 엔진에서 사용 중인 기술품질 점수 산출 공식은 다음과 같습니다.
> **`production_technical_score = (0.32 * KonIQ + 0.24 * FLIVE_image) / 0.56`**
> (약 **4/7 KonIQ + 3/7 FLIVE_image**의 비중으로 결합)

이 공식은 단순한 제안이 아니라, 현재 `src/infer/select_best_shots.py` 등 실제 소스 코드에 구현되어 서비스 중인 로직임을 확인하였습니다.

## 5. 주요 결과
학계 표준 지표인 SRCC(순위 상관 계수)와 PLCC(선형 상관 계수), 그리고 오차 지표인 MAE(평균 절대 오차)를 산출한 결과입니다.

| 데이터셋 | 평가 모델 | SRCC (순위 상관) | MAE (오차) | Bias (편향) |
|:---|:---|:---:|:---:|:---:|
| **SPAQ** | **Production (기준선)** | **0.8730** | 11.89 | **+7.71** |
| | KonIQ 단독 | 0.8555 | **9.58** | -0.32 |
| | FLIVE 단독 | 0.8267 | 20.88 | +18.42 |
| **KonIQ-10k** | **Production (기준선)** | 0.9345 | **3.26** | +1.95 |
| | KonIQ 단독 | **0.9369** | 5.18 | -3.51 |
| **FLIVE** | **Production (기준선)** | 0.5744 | 5.61 | -3.91 |
| | FLIVE 단독 | **0.6603** | **3.80** | +0.95 |

*모든 결과에서 Production 점수는 0~100 범위를 안정적으로 유지하였습니다.*

## 6. 해석
- **일반화 성능 향상**: Production 앙상블 모델은 SPAQ 데이터셋에서 단독 모델들보다 높은 SRCC(0.8730)를 기록하며 가장 우수한 일반화 성능을 보였습니다.
- **편향 완화**: FLIVE 단독 모델이 SPAQ에서 보인 심각한 양의 편향(+18.42)을 Production 모델은 +7.71로 크게 완화시켰습니다.
- **도메인 강점 유지**: KonIQ 데이터셋에서 Production 모델은 KonIQ 단독 모델의 높은 순위 상관(0.9369 -> 0.9345)을 대부분 유지하면서도, 점수 오차(MAE 5.18 -> 3.26)는 오히려 줄어드는 안정성을 보였습니다.
- **결론**: 기존 프로덕션 모델은 개별 모델의 약점을 보완하고 강점을 잘 결합하고 있어, 현재 기술 수준에서 최선의 기준선으로 판단됩니다.

## 7. 최종 결정
- **기존 프로덕션 모델(technical_score)을 프로젝트의 공식 Baseline으로 확정합니다.**
- 성능이 압도적이지 않은 C6 모델로의 교체나 임의의 공식 변경은 수행하지 않습니다.
- 향후 모든 기술품질 개선 시도는 본 보고서에서 확정된 4,967장의 테스트셋에서 현재 Baseline의 성능을 능가해야만 프로덕션 적용이 가능합니다.

## 8. 한계
- 본 평가는 전체 이미지(Image-level) 테스트에 국한되었으며, 패치 단위 평가는 포함되지 않았습니다.
- 오프라인(WSL/Linux) 환경에서의 TFLite 추론 결과이며, 안드로이드 실제 단말에서의 런타임 동작은 별도의 검증이 필요합니다.
- 새로운 모델 학습이나 프로덕션 소스 코드의 직접적인 수정은 이번 단계의 범위에 포함되지 않았습니다.
