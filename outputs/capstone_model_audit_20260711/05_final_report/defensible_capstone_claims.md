# Defensible Capstone Claims

## How to use this register

Every `Original claim` in this file is already a bounded candidate claim. Use the replacement wording verbatim or preserve all of its qualifications. Evidence level and “Safe to use” apply to the original claim in the same row; broader false claims are listed only in `prohibited_or_unsafe_claims.md`.

This file uses the same controlled evidence levels as `prohibited_or_unsafe_claims.md`: `DIRECTLY_PROVEN`, `STRONGLY_SUPPORTED`, `STRONG_BUT_INCOMPLETE`, `WEAKLY_SUPPORTED`, `UNSUPPORTED`, `REFUTED`, and `UNVERIFIED`. In particular, `STRONG_BUT_INCOMPLETE` is never treated as directly proven.

“Safe to use” never extends beyond the row's stated scope and required qualification.

## Presentation boundary

The safest capstone narrative is that the project built and evaluated a broad family of technical and aesthetic scoring systems, identified a conservative local server baseline, produced several mobile conversion candidates, and explicitly rejected weaker replacement lines. It is not defensible to collapse those outcomes into one claim of paper-faithful reproduction or verified end-to-end production deployment.
